# Reviews

Point-in-time reviews of the codebase: architecture, performance, security. They form the backlog of
findings that future work draws from.

## Conventions

- **File name:** `YYYY-MM-DD-<topic>.md` (for example `2026-09-12-architecture-review.md`), dated on the day
  of the review.
- **Record the baseline** (branch and commit) and how each finding was verified (reproduced or code-read).
- **Stable IDs:** each finding gets an ID scoped to its review (`AR-01`, …). Refer to one as
  `<date> <ID>`, for example `2026-09-12 AR-05`, in intents, commit messages and PRs.
- **Finding bodies are immutable.** After publishing, two parts of a review stay maintained and nothing
  else changes:
  - the **Status** column of the index: `Open`, `In progress (<link to intent/PR>)`, `Done (#PR)`, or
    `Won't fix (<reason>)`. If a finding turns out to be wrong, mark it `Won't fix (invalid)` instead of
    deleting it;
  - the optional **`## Dependencies`** table (see below).

  New observations go into a new review, never into an existing finding's body.
- **Dependencies.** A review may carry a `## Dependencies` table recording edges between findings, so
  "what can I start right now" is data rather than prose. Only record edges the review text supports.

  | Edge | Meaning |
  |---|---|
  | `needs` | From is blocked until To is resolved |
  | `resolves` | Doing From closes To as a side effect |
  | `duplicates` | Same defect as To, recorded in a different review |
  | `related` | Read or do them together; neither blocks the other |

  `To` is a bare ID for this review (`AR-16`) or a dated one for another (`2026-09-20 AR-01`). Both
  reviews define an `AR-01`, so cross-review references must always be dated.
- **Shipped fixes** must also update the living docs (`docs/system-design.md` *Known issues*,
  `docs/websocket-protocol.md`, the README) so those always describe the current state.

- **Per-mutation allocation profile on the delta path.** The pooled struct-of-arrays idea for
  `MutationInfo.ChangedColumns` was deferred out of the AR-08 work because the array escapes further than
  expected: `FilterChangedColumns` can return the mutation's own array, it lands in
  `RowUpdateDelta.ChangedColumns`, and `WebSocketOutboundPublisher.FlushAsync` skips any subscription with
  `IsSnapshotActive`, so those delta objects accumulate for a client mid-snapshot and returning a pooled
  buffer would corrupt its data. Should start from a `[MemoryDiagnoser]` profile of the real allocation
  mix, likely dominated by per-subscriber frame encoding (2026-09-12 AR-13, AR-14). Source:
  [../changes/2026-09-13-fieldmask-dynamic-width/intent.md](../changes/2026-09-13-fieldmask-dynamic-width/intent.md)
